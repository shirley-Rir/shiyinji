# 当前完成度与实施顺序

## 1. 当前版本结论

Demo V1 已经验证了产品的交互形态：用户能表达情境，看到系统对情境的理解，获得一首首选和四首备选，完成播放和反馈。它目前还没有验证“推荐是否真的准确”，因为所有歌曲、画像和历史都是前端模拟数据。

## 4. 当前代码中的模拟点

- `app/music-app.tsx` 中的 `TRACKS` 是固定演示曲目。
- `orderTracks` 使用关键词正则切换曲目顺序。
- `context` 标签同样来自关键词判断。
- 历史、画像和连接状态都是静态内容。
- 喜欢、方向调整和隐私开关只存在于 React 内存状态。
- 页面没有调用任何拾音记业务 API。

这些模拟点是下一轮替换边界，不应继续向当前单文件组件叠加业务逻辑。

## 5. 推荐的实施顺序

```mermaid
flowchart LR
    A[阶段 A<br/>领域类型与数据库] --> B[阶段 B<br/>API 骨架与 Mock Provider]
    B --> C[阶段 C<br/>大模型情境理解]
    C --> D[阶段 D<br/>真实音乐 Provider]
    D --> E[阶段 E<br/>推荐召回与排序]
    E --> F[阶段 F<br/>事件与画像学习]
    F --> G[阶段 G<br/>封闭测试与调权]
```

### 阶段 A：数据地基

- 定义 `StructuredContext`、`UserProfile`、`Track`、`Recommendation` 和事件类型。
- 建立用户、画像、连接、情境、曲目、特征、推荐和事件表。
- 建立 Repository 接口和迁移测试。

### 阶段 B：API 骨架

- 实现情境、推荐、播放、反馈和历史 API 的请求校验。
- 先用 `MockAIProvider` 和 `MockMusicProvider` 打通完整服务端链路。
- 把前端固定数据替换成 API 调用，但保持当前视觉体验不变。

### 阶段 C：大模型语义理解

- 接入多模态模型的结构化输出。
- 完成置信度、图文冲突、单问题消歧和安全分支。
- 建立 30 到 50 条情境测试集，避免只靠肉眼试用。

### 阶段 D：音乐 Provider

- 接入封闭环境网易云登录、歌单导入、搜索和播放校验。
- 禁用解灰、代理、随机 IP 和音源替换。
- 建立开放授权音频降级曲库。

### 阶段 E：推荐主链

- 建立 100 到 300 首种子曲目的基础特征。
- 实现四路候选召回、硬过滤、加权排序和 Top 5 多样化。
- 保存每次候选分数、过滤原因和画像版本。

### 阶段 F：反馈学习

- 接入播放事件和显式反馈。
- 区分当前情境、场景画像和长期画像的影响范围。
- 提供撤销和画像版本追踪。

## 6. 下一轮建议范围

下一轮只动“阶段 A + 阶段 B”，不要立即同时接入大模型和网易云。完成标准是：当前界面不变，但所有页面数据经过真实 API 和数据库流转；Provider 仍可使用 Mock。这样后续接模型和音乐平台时，问题会被隔离在适配层，而不是重新改整套前端。
